# Shared browser packages

Use Node 24 and Python 3.12: `npm ci`, `npm test`, `FIREFOX_ADDON_ID=YOUR_STABLE_ID npm run build`, `npm run lint`. The Chrome ZIP retains its original filename and manifest. Firefox receives distributor-owned identity and Firefox 140+ consent declarations; CI uses an explicitly non-production fixture. Both archives contain the same popup/content code and deterministic timestamps, plus revision/version/checksum evidence. No identity is selected for the distributor.

Data audit: content code reads the current GameBanana URL, mod title/category, preview URL and selected filenames/download links. Clicking Import transfers them outside the browser to the local PMM handler. This is browsing activity and website content under [Mozilla's taxonomy](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/), so declaring `none` would be inaccurate. No account/cookie collection, telemetry or remote analytics is introduced. Firefox 140+ supplies built-in consent before these data categories can be transmitted.

Grant GameBanana site access, open a mod page, select downloads and launch PMM. A request cannot establish application receipt or completion. Permission/messaging failures must leave retry available. The extension has no acknowledged status protocol. Test temporary loading via `about:debugging` separately from signed installation.

For self-distribution, the maintainer owns the production ID and Mozilla signing account (issue #5). Configure an environment named `firefox-signing`, with `WEB_EXT_API_KEY` and `WEB_EXT_API_SECRET` as secrets. Dispatch Sign self-distributed Firefox package with the same stable ID for every version. `web-ext sign --channel=unlisted` submits to Mozilla and returns an XPI. No public AMO listing is required. Secrets are supplied by environment, never archive content or command arguments. Review/approval and installed-browser validation remain human work; missing credentials or fixture identity fails signing.

Native Chrome/Firefox and confined browser/portal handoff remain pending interactive validation. Node/manifest tests and lint do not establish installed Firefox imports or Flatpak/Snap support. Record browser/OS/desktop versions, cold/running app results, signed vs temporary build, and launch request versus completed import for issue #5. Self-distributed update hosting is not implemented; distribute later signed versions explicitly until a validated update URL is configured.

## Branch integration

Feature/issue PRs target `dev`; only the same repository's `dev` promotes into `main`. `dev` starts from the current reviewed main baseline without rewriting history. Browser package validation runs for PRs and pushes to dev/main. A separate metadata-only target-branch workflow supplies **Trusted promotion source**, refusing feature/fork branches into main without checking out PR code or granting token permissions.

The maintainer must require **browser-checks** and **Trusted promotion source** in repository rules, forbid direct main pushes/force pushes, review workflow changes and record any bootstrap bypass. Initial trusted-workflow installation on main requires a reviewed dev promotion before that check can be required there. This PR prepares the workflow; no importer branch-protection settings are activated. Signing remains a separate protected manual operation with the identity/credentials and installed-browser validation owned by issue #5.
